# AI Research Assistant — 优化功能测试指南

> 测试范围：事件埋点补全、仪表盘项目筛选、上下文注入增强、文献哨兵自动检查
> 前置条件：`npm run build` 和 `cargo check` 均通过

---

## 一、启动应用

```bash
npm run tauri dev
```

---

## 二、事件埋点测试（Event Tracking）

### 2.1 Zotero 同步事件

1. 打开主窗口 → 切换到 Knowledge Base 面板
2. 切换到 **Zotero** 标签
3. 点击 **Sync Zotero** 按钮
4. 等待同步完成（成功或失败均可）
5. 打开 DevTools Console (F12)，输入：`await queryEvents()`
6. **预期结果**：最近一条记录的 `event_type` 为 `zotero_sync`，`metadata` 中包含 `items_synced`、`collections_synced`、`success`

### 2.2 知识库索引事件

1. 在 Knowledge Base 的 **Local Docs** 标签下，点击 **Add Folder**
2. 选择一个包含 PDF 的文件夹，等待索引完成
3. 打开 DevTools Console，输入：`await queryEvents()`
4. **预期结果**：
   - 有两条记录：`kb_index_start`（source: folder）和 `kb_index_complete`
   - `kb_index_complete` 的 `metadata` 中包含 `documents_added` 和 `success: true`
   - `duration_ms` 有值

### 2.3 知识库重新索引事件

1. 在 Local Docs 列表中，找一个 `status` 为 `error` 的文档
2. 点击该文档的 **retry** 按钮
3. 打开 DevTools Console，输入：`await queryEvents()`
4. **预期结果**：
   - `kb_index_start`（source: reindex）和 `kb_index_complete`
   - `resource_id` 为该文档的 ID

### 2.4 综述生成事件

1. 打开主窗口 → Knowledge Base 面板 → 点击 **📚 生成综述**
2. 按向导选择 2-3 篇文献 → 选择综述风格 → 点击 **开始生成**
3. 等待生成完成
4. 打开 DevTools Console，输入：`await queryEvents()`
5. **预期结果**：
   - `synthesis_start`：metadata 包含 `source`、`paper_count`、`review_style`
   - `synthesis_complete`：metadata 包含 `sections_generated`、`success: true`、`duration_ms`

### 2.5 事件数量汇总验证

1. 依次完成上述操作后，打开主窗口侧边栏 → **Dashboard（仪表盘）**
2. **预期结果**：
   - Activity Breakdown 中出现：Zotero同步、知识库索引、综述生成 的统计条
   - 各事件类型的计数与实际发生次数一致

## 三、仪表盘项目筛选测试

### 3.1 项目筛选下拉框

1. 打开主窗口 → 点击侧边栏 **Dashboard** 按钮
2. 观察时间范围按钮（本周/本月/本季）下方，应出现 **项目** 筛选下拉框
3. **预期结果**：下拉框默认显示当前项目名称，选项包含「全部项目」和所有已创建项目

### 3.2 筛选数据变化

1. 确保有至少 2 个项目，且各自有一些聊天记录/待办/文献
2. 在 Dashboard 中选择 **项目 A**
3. **预期结果**：Summary Cards 中的 AI对话/写作操作/模型消耗 数据仅统计项目 A
4. 切换到 **项目 B**
5. **预期结果**：数据变化为项目 B 的统计
6. 切换到 **全部项目**
7. **预期结果**：数据汇总所有项目

### 3.3 时间范围 + 项目筛选交叉验证

1. 选择 **本周** + **项目 A**
2. 记录 AI对话 次数
3. 切换为 **本月** + **项目 A**
4. **预期结果**：本月次数 >= 本周次数（或等于，如果本月只有本周有数据）
5. 切换为 **本周** + **全部项目**
6. **预期结果**：全部项目的次数 >= 单个项目次数

### 3.4 每日活跃趋势图

1. 在不同项目和不同时间范围之间切换
2. **预期结果**：趋势图的数据随筛选条件实时更新，柱状图高度变化合理

## 四、上下文注入增强测试

### 4.1 待办提醒注入

1. 选择一个项目（确保该项目有待办事项）
2. 打开 Todo 面板，手动添加一个待办："需要验证 KL 散度作为评估指标"
3. 返回聊天窗口，发送消息："我应该用什么评估指标？"
4. **预期结果**：AI 的回答中可能会引用或提及待办中的内容，或给出与待办相关的建议
5. （验证方式：打开 DevTools Console，查看 `[Context]` 日志，或观察 AI 回答是否自然提及待办）

### 4.2 无待办时的静默

1. 选择一个没有待办事项的项目（或创建一个空项目）
2. 发送任意消息
3. **预期结果**：系统提示词中不包含 "Pending todos" 段落，AI 回答正常

### 4.3 新文献提醒注入

1. 确保当前项目有 **Sentinel 监控主题**，且手动检查后发现了一些新论文（不要标记为已读）
2. 返回聊天窗口，发送消息："最近有什么新进展？"
3. **预期结果**：AI 回答中可能提及 "本周有 N 篇新论文到达" 或类似提示
4. 将所有哨兵论文标记为已读
5. 再次发送消息
6. **预期结果**：系统提示词中不再包含新文献提醒段落

### 4.4 全部上下文叠加

1. 选择一个有知识库文档、有待办、有未读哨兵论文、有历史会话的项目
2. 发送一条与研究内容相关的消息
3. **预期结果**：AI 回答能综合利用：
   - 知识库中的相关文献片段
   - 历史会话摘要
   - 待办提醒
   - 新文献提醒

## 五、文献哨兵自动检查与红点提醒

### 5.1 项目统计栏新论文徽章

1. 创建一个项目，添加一个 Sentinel 监控主题（关键词：「transformer」）
2. 在 Sentinel 面板点击该主题的 **手动检查**
3. 等待检查完成，应发现若干新论文
4. **预期结果**：
   - 主窗口顶部项目统计栏出现红色徽章：`📡 N new papers`
   - 徽章颜色为红色，鼠标悬停变为亮红色
   - 点击徽章打开 Sentinel 面板

### 5.2 徽章消失验证

1. 在 Sentinel 面板中，将所有未读论文标记为「已读」或「忽略」
2. 返回主窗口
3. **预期结果**：项目统计栏的 `📡 N new papers` 徽章消失

### 5.3 项目切换时的徽章变化

1. 项目 A 有未读哨兵论文，项目 B 没有
2. 从项目 A 切换到项目 B
3. **预期结果**：统计栏徽章消失
4. 切回项目 A
5. **预期结果**：徽章重新出现，数字正确

### 5.4 自动检查功能（需要等待 6 小时，可通过修改代码加速验证）

如需验证自动检查，可临时修改 `MainWindow.vue` 中的定时器间隔：

```typescript
// 将 6 * 60 * 60 * 1000 改为 60 * 1000（1分钟）进行测试
```

1. 修改后重启应用
2. 确保有活跃的 Sentinel 监控主题
3. 等待 1 分钟
4. **预期结果**：系统自动查询 arXiv，如果有新论文，会自动存入数据库，项目统计栏徽章更新
5. 在 Dashboard 中应能看到新的 `sentinel_check` 事件（source: auto）

## 七、已知限制（非 Bug）

1. **哨兵自动检查在前端执行**：虽然定时器在后台运行，但应用关闭后不会检查。这是设计简化，完整后端定时任务可后续通过 Rust `tokio::time::interval` 实现。
2. **arXiv 请求频率**：自动检查每 6 小时一次，每个活跃主题查询一次 arXiv。如果主题过多，可能触发 arXiv 的速率限制。
3. **项目统计栏徽章不实时刷新**：当 Sentinel 面板中标记论文为已读时，主窗口的徽章不会立即消失（需要切换项目或等待下次 stats 加载）。可接受的小延迟。
