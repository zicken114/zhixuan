# Phase 5 功能测试指南

> 测试范围：5.2 插件与扩展市场 + 5.3 团队科研空间
> 前置条件：已执行 `npm run build` 和 `cargo check` 均通过

---

## 一、启动应用

```bash
cd src-tauri && cargo run
```

或前端开发模式：
```bash
npm run tauri dev
```

---

## 二、5.2 插件市场测试

### 2.1 界面入口

1. 打开主窗口
2. 观察顶部工具栏最右侧，确认新增两个按钮：
   - 拼图图标（插件市场）
   - 人群图标（团队空间）
3. 悬停查看 tooltip 是否显示正确

### 2.2 "发现" 标签页

1. 点击拼图图标，打开插件面板
2. 默认应显示在 **Installed** 标签
3. 点击 **Discover** 标签
4. **预期结果**：
   - 显示 5 个插件卡片：BLAST Helper、Molecule Drawer、LaTeX Formatter、Citation Validator、Word Cloud Generator
   - 每个卡片显示：名称、版本、作者、描述、评分星号、安装次数、权限标签
   - 顶部有分类筛选按钮：All / 学科专用 / 写作增强 / 文献工具 / 可视化
5. 点击 **"写作增强"** 分类筛选
6. **预期结果**：只显示 LaTeX Formatter
7. 点击 **"All"** 恢复全部显示

### 2.3 安装插件

1. 在 Discover 页找到 **"LaTeX Formatter"**
2. 点击 **Install** 按钮
3. **预期结果**：
   - 按钮文字变为 "Installing..."
   - 短暂后弹出 alert："Plugin installed successfully"
   - 按钮文字变为 "Installed" 且置灰不可点
4. 切换到 **Installed** 标签
5. **预期结果**：LaTeX Formatter 出现在已安装列表中，开关为开启状态（绿色）

### 2.4 安装多个插件

1. 返回 Discover，依次安装 **Word Cloud Generator** 和 **Citation Validator**
2. 切换到 Installed 标签
3. **预期结果**：三个插件都显示，且顺序按安装时间倒序

### 2.5 开关插件

1. 在 Installed 页，点击 LaTeX Formatter 的开关
2. **预期结果**：
   - 开关滑到左侧，变为灰色
   - 卡片整体变暗（opacity: 0.6）
3. 再次点击开关
4. **预期结果**：开关恢复绿色，卡片变亮

### 2.6 卸载插件

1. 点击 Citation Validator 卡片的 **Uninstall** 按钮
2. 确认弹窗出现，点击确认
3. **预期结果**：卡片从 Installed 列表消失
4. 切换到 Discover 页
5. **预期结果**：Citation Validator 的按钮恢复为可点击的 "Install"

### 2.7 空状态

1. 卸载所有已安装插件
2. **预期结果**：
   - Installed 页显示 "No plugins installed yet."
   - 下方有 "Browse marketplace →" 链接
3. 点击链接
4. **预期结果**：自动切换到 Discover 标签

### 2.8 边界测试

| 测试项 | 操作 | 预期结果 |
|--------|------|----------|
| 重复安装 | 对已安装的插件再次点击 Install | 按钮为置灰状态，不可点击 |
| 快速点击 | 快速连续点击 Install | 只有第一次生效，后续被忽略 |
| 面板切换 | 打开插件面板后，点击仪表盘/实验/哨兵等按钮 | 插件面板应自动关闭，互斥正确 |
| 关闭按钮 | 点击插件面板右上角的 × | 面板关闭 |

## 三、5.3 团队空间测试

### 3.1 无团队状态

1. 首次打开主窗口，点击人群图标
2. **预期结果**：
   - 显示 "No Teams Yet" 空状态页面
   - 中间有 emoji 图标 👥
   - 两个按钮：Create Team / Join Team

### 3.2 创建团队

1. 点击 **Create Team** 按钮
2. 弹出模态框，输入团队名：**"测试课题组"**
3. Sync Mode 保持默认 **P2P Direct Connect**
4. 点击 **Create**
5. **预期结果**：
   - 弹窗关闭
   - 左侧出现团队列表，显示 "测试课题组"
   - 右侧显示团队详情页面
   - Members 区域显示 1 人（Owner）

### 3.3 生成邀请码

1. 在团队详情页，点击右上角 **Invite** 按钮
2. **预期结果**：弹出 alert，显示 6 位数字邀请码（如 "123456"）
3. 记录下这个邀请码

### 3.4 加入团队

1. 模拟另一个成员加入（在同一界面测试即可）
2. 先删除当前团队，重新创建一个，记录邀请码
3. 或者测试逻辑：点击 **Join Team** 按钮
4. 输入刚才记录的邀请码
5. Your name 输入 **"李四"**
6. 点击 **Join**
7. **预期结果**：
   - 弹窗关闭
   - 成功加入团队，左侧团队列表显示该团队
   - Members 区域显示 2 人：Owner + 李四

### 3.5 团队切换

1. 创建第二个团队：**"另一个实验室"**
2. **预期结果**：左侧列表显示两个团队
3. 点击第一个团队
4. **预期结果**：右侧内容切换回第一个团队的详情
5. 点击第二个团队
6. **预期结果**：右侧切换，Members 只有 Owner 1 人

### 3.6 删除团队

1. 选择一个团队，点击右上角红色的 **Delete** 按钮
2. 确认弹窗出现，点击确认
3. **预期结果**：
   - 该团队从左侧列表消失
   - 如果还有其他团队，自动选中第一个
   - 如果没有团队了，回到 "No Teams Yet" 空状态

### 3.7 边界测试

| 测试项 | 操作 | 预期结果 |
|--------|------|----------|
| 空团队名 | Create Team 时不输入名称直接点击 Create | 应无反应（前端拦截） |
| 错误邀请码 | Join Team 时输入任意错误数字 | 弹出 alert："Failed to join team: Invalid invite code" |
| 过期邀请码 | 使用已过期的邀请码（需修改系统时间或数据库） | 弹出 alert："Invite code has expired" |
| 互斥面板 | 打开团队面板后，点击插件/仪表盘/实验等按钮 | 团队面板应自动关闭 |
| 关闭按钮 | 点击团队面板右上角的 × | 面板关闭 |

## 四、综合测试

### 4.1 面板互斥性

按以下顺序依次点击各面板按钮，**预期结果**：每次只有一个面板打开，其他自动关闭。

1. 打开 History（时钟图标）→ 再打开 Knowledge（书本图标）→ History 关闭
2. 打开 Todos（清单图标）→ 再打开 Writing History（笔图标）→ Todos 关闭
3. 打开 Sentinel（铃铛图标）→ 再打开 Experiment（闪电图标）→ Sentinel 关闭
4. 打开 Dashboard（图表图标）→ 再打开 Plugin（拼图图标）→ Dashboard 关闭
5. 打开 Team（人群图标）→ 再打开 Plugin（拼图图标）→ Team 关闭
6. 打开 History → 再打开 Team → History 关闭

### 4.2 新聊天重置面板

1. 打开任意侧边面板（如 Plugin）
2. 点击左上角 **New Chat**（+ 图标）
3. **预期结果**：所有侧边面板关闭，进入新聊天状态

### 4.3 加载历史记录

1. 打开任意侧边面板
2. 打开 History 面板，点击某条历史记录加载
3. **预期结果**：所有侧边面板关闭，聊天记录加载到主区域

## 五、已知限制（非 Bug）

以下行为是已知的设计简化，不属于 Bug：

1. **插件数据未持久化到 SQLite**：插件安装状态保存在 Rust 内存中，应用重启后丢失。这是因为插件系统当前以演示/registry 为主，完整持久化可后续通过前端 `useDatabase.ts` 实现。
2. **团队数据未持久化**：同理，团队、成员、活动数据当前保存在 Rust 内存中，重启后丢失。
3. **邀请码为 6 位数字**：简化实现，实际应生成更复杂的随机字符串。
4. **P2P / Server 模式仅为标记**：实际的同步、加密、CRDT 实现需要额外的大量工作，当前仅保存配置字段。
5. **插件市场为内置 Mock 数据**：当前 registry 是硬编码的 5 个插件，未连接远程服务器。
6. **成员在线状态为静态**：last_seen_at 在加入时设置，不会自动更新心跳。
